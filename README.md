# christianpipal.com

Personal academic website. Static HTML generated by a small Python script (`build.py`) from YAML files,
deployed to GitHub Pages by a GitHub Action on every push.

## Where things live

| To change… | edit |
|---|---|
| bio, links, news, featured papers on the home page | `content/site.yml` |
| papers (title, authors, abstract, links, key figure) | `content/publications.yml` |
| research lines, clusters, projects — and which paper belongs where | `content/research.yml` |
| teaching | `content/teaching.yml` |
| web CV | `content/cv.yml` |
| portrait | `static/img/portrait.jpg` (square, ~600×600) |
| key figures | `static/figures/<paper-id>.png`, then `figure: figures/<paper-id>.png` + `figure_caption:` in publications.yml |
| CV PDF | `cv/cv.tex` → compile, copy to `static/files/cv.pdf` (see below) |
| look & feel | `static/css/style.css`, `templates/*.html` |

### Adding a paper

1. Add an entry to the right section in `content/publications.yml` (copy an existing one).
2. Add its `id` to one or more clusters in `content/research.yml` (this sets its research-line tags) and,
   if applicable, to a project's `papers:` list.
3. Optional: drop a key figure into `static/figures/` and reference it.

Working papers: only list papers that have a public preprint (SocArXiv, OSF, arXiv, SSRN …).

## Public CV

`cv/cv.tex` is the web version of the CV: `\reviewmode` is set to 3, so no journal names appear for work
under review or R&R, and `\preprint{url}` adds a "[preprint]" link. After editing:

```bash
cd cv && latexmk -pdf cv.tex && cp cv.pdf ../static/files/cv.pdf && cd ..
```

## Preview locally

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # once
.venv/bin/python build.py serve                                     # http://localhost:8000
```

The preview rebuilds automatically when you reload the page after editing a file.

## Publish

Push to `main`; the action in `.github/workflows/deploy.yml` builds and deploys the site.

### One-time setup

1. Create a GitHub repo (e.g. `cpipal/christianpipal.com`) and push this folder.
2. Repo **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Repo **Settings → Pages → Custom domain**: `christianpipal.com` → Save.
4. In **Cloudflare → christianpipal.com → DNS**, add (all as **DNS only / grey cloud** at first):

   | Type | Name | Content |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | CNAME | `www` | `cpipal.github.io` |

   Remove any conflicting A/AAAA/CNAME records for `@` and `www` (e.g. Cloudflare parking records).
5. Wait until GitHub shows the domain as verified and the certificate is issued (minutes to an hour),
   then tick **Enforce HTTPS** in the Pages settings.
6. Optional afterwards: switch the records to **Proxied** (orange cloud) and set Cloudflare
   **SSL/TLS → Full**. Not required — GitHub already serves HTTPS.
